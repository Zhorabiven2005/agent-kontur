# ТЗ: промокоды при записи на лабораторию

*Учебная постановка. Сервис, данные и ошибки придуманы для проверки навыка `review-spec`.*

## 1. Контекст

Онлайн-школа проводит лаборатории (потоки обучения). Участник записывается через сайт или Telegram-бота. Оба канала вызывают метод `POST /api/v1/registrations` сервиса записи.

Маркетинг хочет раздавать промокоды партнёрам. Промокод даёт скидку в процентах от цены лаборатории.

## 2. AS-IS

### 2.1. Метод `POST /api/v1/registrations`

Request:

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `lab_id` | string | да | Идентификатор лаборатории |
| `participant_id` | string | да | Идентификатор участника |

Response `201`:

| Поле | Тип | Описание |
|---|---|---|
| `registration_id` | string | Идентификатор записи |
| `status` | string | Всегда `awaiting_payment` |
| `price` | integer | Цена лаборатории в рублях |

Ошибки:

| Код | Когда |
|---|---|
| `404` | Лаборатория не найдена |
| `409` | Участник уже записан на эту лабораторию |

### 2.2. Статусы записи

`awaiting_payment` → `paid` → `completed`; из `awaiting_payment` возможен переход в `cancelled`.

Через 24 часа в статусе `awaiting_payment` сервис уведомлений отправляет участнику напоминание об оплате. Статус `paid` выставляет платёжный сервис после успешной оплаты.

## 3. TO-BE

### 3.1. Справочник промокодов

Новая таблица `promo_codes`:

| Поле | Тип | Описание |
|---|---|---|
| `code` | integer | Промокод |
| `discount_percent` | integer | Скидка, 1–100 |
| `valid_to` | date | Действует до |
| `usage_limit` | integer | Сколько раз можно применить |
| `used_count` | integer | Сколько раз применён |

Промокоды заводит маркетинг через админку.

### 3.2. Изменение метода `POST /api/v1/registrations`

В request добавляется необязательное поле `promo_code` (integer).

Алгоритм:
1. Если `promo_code` передан — найти его в `promo_codes`.
2. Проверить, что промокод действует (`valid_to` не прошёл) и `used_count < usage_limit`.
3. Рассчитать `price` = цена лаборатории × (100 − `discount_percent`) / 100.
4. Если `price` = 0, создать запись сразу в статусе `paid`.
5. Увеличить `used_count` на 1.
6. Вернуть ответ.

Если промокод не найден, истёк или исчерпан — вернуть `409` с текстом «Промокод недействителен».

### 3.3. Ответ

Поле `price` в ответе теперь содержит цену с учётом скидки.

## 4. Критерии приёмки

1. Участник вводит действующий промокод на 20% — `price` в ответе на 20% меньше цены лаборатории.
2. Участник вводит промокод на 100% — запись создаётся, `price` = 0.
3. Запрос без промокода работает как раньше.
